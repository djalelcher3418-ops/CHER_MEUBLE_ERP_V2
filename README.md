# CHER MEUBLE ERP

نظام تسيير ورشة CHER MEUBLE — TypeScript + React + Vite + Supabase، يُنشر على Cloudflare Pages.

## المرحلة 1
- تسجيل الدخول (مدير / عامل)
- المواد: إضافة، تعديل، جرد، سجل الحركات، طباعة ملصقات الباركود
- الموردون: الحساب، الدفعات، كشف الحساب، الدين القديم
- المشتريات: فاتورة بعدة أسطر، دفع جزئي، تدخل المواد للمخزون تلقائيًا
- إخراج المواد: مسح الباركود بكاميرا الهاتف (العامل لا يرى الأسعار)
- الرئيسية: قيمة المخزون، الديون، المواد الناقصة، آخر ما خرج

## المرحلة 2
- الزبائن: الحساب، الدفعات، كشف الحساب، الدين القديم
- الطلبيات: عدة أسطر، تخفيض، عربون، موعد التسليم، الحالة (جديدة، في الورشة، جاهزة، سُلّمت، ملغاة)
- فاتورة الطلبية: طباعة أو حفظ PDF
- ربط المواد المُخرَجة بالطلبية: تكلفة المواد والربح التقريبي لكل طلبية
- الطلبية تنتقل تلقائيًا إلى «في الورشة» عند خروج أول مادة لها
- الرئيسية: ما لك عند الزبائن، الطلبيات الجارية، مواعيد التسليم والمتأخرة

## المرحلة 3
- العمّال: أجر يومي، تقويم الحضور (غياب / نصف يوم)، التسبيقات، دفع راتب الفترة (من 15 إلى 14)
- صفحة «راتبي» للعامل المربوط بحساب: يرى حضوره وراتبه فقط
- المصاريف العامة حسب الصنف (كراء، كهرباء، نقل…)
- تقرير الشهر: الحركة النقدية، وربح الطلبيات المسلّمة بعد المواد والأجور والمصاريف

## المرحلة 4
- لوحة «الورشة»: العامل يرى الطلبيات الجارية وأسطرها وملاحظاتها بدون أي مبلغ
- العامل ينقل الطلبية خطوة واحدة: «بدأنا العمل» ثم «الطلبية جاهزة»، وزر لإخراج المواد لها مباشرة
- سجل الحالات في تفاصيل الطلبية: من غيّر الحالة ومتى
- زر واتساب للزبون برسالة جاهزة حسب حالة الطلبية والباقي للدفع
- الصفحات تُحمَّل عند فتحها فقط، فيفتح التطبيق أسرع على الهاتف

## المرحلة 5: الرسائل وتصميم الهاتف
- الرسائل: دردشة «كل الفريق» + دردشة خاصة بين الإدارة وكل عامل، مع الصور
- تصل الرسائل فورًا، مع عدد غير المقروء وعلامة القراءة (✓✓)
- تنبيه على الهاتف عند وصول رسالة والتطبيق في الخلفية (بعد تفعيل التنبيهات)
- تصميم جديد للهاتف: شريط تبويب سفلي، أزرار كبيرة، نوافذ تنزلق من الأسفل، الجداول تصبح بطاقات، ووضع ليلي تلقائي

## المرحلة 6: التنبيهات والتطبيق مغلق
- تنبيه على الهاتف عند وصول رسالة، حتى والتطبيق مغلق (Web Push)
- تنبيه للمدير عندما يبدأ عامل العمل على طلبية أو يجعلها جاهزة
- يعمل على أندرويد، وعلى الآيفون (iOS 16.4 فما فوق) بعد إضافة التطبيق إلى الشاشة الرئيسية

### نشر دالة التنبيهات (مرة واحدة)
1. Supabase → Edge Functions → Deploy a new function → Via Editor
2. الاسم: `send-push`
3. الصق محتوى الملف `supabase/functions/send-push/index.ts` ثم Deploy
4. اترك خيار Verify JWT مفعّلًا. لا حاجة لأي مفتاح: الدالة تنشئ مفاتيحها وتحفظها بنفسها أول مرة.

## المرحلة 7: حسابات الدخول بالهاتف
- صفحة «الحسابات» (من «المزيد»): إنشاء حساب لكل عامل برقم هاتفه ورمز سري من 6 أرقام، وإرساله له عبر واتساب
- رمز جديد لمن نسي رمزه، وإيقاف الحساب أو إعادة تفعيله
- الدخول برقم الهاتف أو بالبريد الإلكتروني (حساب المدير الحالي يبقى كما هو)
- «حسابي» (بالضغط على الاسم في الأعلى): تغيير الرمز السري وتسجيل الخروج

### نشر دالة الحسابات (مرة واحدة)
مثل دالة التنبيهات: Supabase → Edge Functions → Deploy a new function → Via Editor،
الاسم `manage-users`، والصق محتوى `supabase/functions/manage-users/index.ts` ثم Deploy.

## المرحلة 8
- «حالة النظام» (من «المزيد»): تعرض ملفات SQL والدوال الناقصة في Supabase وكيف تُكمَّل، وتنبيه في الرئيسية إن نقص شيء
- تصدير Excel من صفحة التقرير: ملف للشهر (الطلبيات المسلّمة، الدفعات، المصاريف، الرواتب) ونسخة احتياطية كاملة
- مصمم الأثاث صار جزءًا من التطبيق المنشور، مع زر للرجوع

## المرحلة 9: إصلاحات الأمان والدقة
- التسجيل المفتوح لا يعطي أي صلاحية: الحساب الجديد يكون موقوفًا ما لم يُنشئه المدير من صفحة «الحسابات»
  (ويُنصح بإطفاء Allow new users to sign up في Supabase → Authentication)
- تكلفة المواد المُخرَجة يحددها الخادم دائمًا، والعامل لا يُخرج أكثر من الموجود ولا لطلبية مسلّمة أو ملغاة
- حفظ الطلبية وأسطرها دفعة واحدة، والتخفيض لا يتجاوز مجموع الأسطر المحفوظة
- مجاميع التقرير والرئيسية تُحسب في قاعدة البيانات (لا حد لعدد الحركات)
- صور الرسائل: لا طلبات متكررة عند الفشل، تجديد الروابط قبل انتهائها، وحذف الصورة مع رسالتها

## المرحلة 10: صور الطلبيات ورابط التتبع
- صور لكل طلبية (التصميم، الرسم، المقاسات، القطعة الجاهزة): يضيفها المدير من تفاصيل الطلبية، والعامل من لوحة الورشة
- العامل يرى صور الطلبيات الجارية فقط، ويحذف ما أضافه هو فقط
- رابط تتبع سري لكل طلبية: يفتحه الزبون بدون حساب ويرى الحالة وموعد التسليم والمبلغ والباقي (الاسم الأول فقط، بلا هاتف)
- الرابط يُضاف تلقائيًا إلى رسالة واتساب للزبون

## المرحلة 11: عروض الأسعار (devis)
- «+ عرض سعر» في صفحة الطلبيات: نفس أسطر الطلبية، بدون عربون
- عرض السعر لا يُحسب دينًا على الزبون، لا يصل للورشة، ولا تُخرج له مواد
- طباعة عرض السعر (صالح 15 يومًا) ورابط للزبون يرى فيه التفاصيل، ويُرسل مع رسالة واتساب
- «الزبون وافق»: يتحوّل إلى طلبية بتاريخ اليوم ويصل للورشة. «الزبون رفض»: يُعلَّم كملغى

## المرحلة 12: مقاس السرير وصوره عند إنشاء الطلبية
- خانة «المقاس» لكل سطر: 90/190، 120/190، 140/190، 160/190، 180/200، أريكة، أو مقاس آخر يُكتب يدويًا
- إن تُرك البيان فارغًا يُكتب تلقائيًا «سرير» أو «أريكة»
- المقاس يظهر في تفاصيل الطلبية، الفاتورة، لوحة الورشة، صفحة الزبون، وملف Excel
- إضافة صور السرير المطلوب مباشرة من نافذة إنشاء الطلبية (تُرفع عند الحفظ)

## المرحلة 13: نوع القماش ونوع الأرجل
- خانتا «القماش» و«الأرجل» لكل سطر في الطلبية، تُكتبان يدويًا
- تظهران في تفاصيل الطلبية، الفاتورة وعرض السعر، بطاقة الورشة للعامل (بدون أسعار)، صفحة تتبع الزبون، وملف Excel

## المرحلة 14: «الفريق» — منشورات وألعاب، وبحث المواد يدويًا
- تبويب «الفريق» بدل «الرسائل»، فيه ثلاث صفحات: **المنشورات**، **الدردشة** (كما كانت)، **الألعاب**
- المنشورات مثل إنستغرام: نص وصورة، تفاعلات ❤️ 👏 😂 🔥 (ضغطتان على الصورة = ❤️)، تعليقات، وبطاقة «🙏 شكر زميل»
- الألعاب: «لعبة الذاكرة» و«حساب الورشة» مع ترتيب أسبوعي (يبدأ السبت) وترتيب كل الأوقات؛ من يصبح الأول ينزل له منشور تهنئة تلقائي
- كل منشور جديد أو شكر يصل تنبيهًا للفريق، وكل تعليق يصل لصاحب المنشور (بعد إعادة نشر دالة send-push)
- المدير يحذف أي منشور أو تعليق؛ كل شخص يحذف ما كتبه
- إخراج المواد: زر «اختيار من المواد الموجودة» مع بحث بالاسم أو الصنف، وخانة البحث تقبل الاسم أيضًا وليس الباركود فقط
- خانتا القماش والأرجل في الطلبية أصبحتا كتابة يدوية فقط (بدون اقتراحات)

## المرحلة 15: لعبة تتريس
- لعبة «تتريس» في صفحة الألعاب: القطع السبع، معاينة القطعة التالية، ظلّ مكان السقوط، والمستوى يزيد كل 10 أسطر
- التحكم على الهاتف: أزرار كبيرة (مع الضغط المطوّل)، أو السحب على اللوحة: يمين/يسار للتحريك، لمسة للتدوير، سحب لأسفل للإسقاط؛ وعلى الكمبيوتر الأسهم والمسافة
- تتوقف تلقائيًا عند الخروج من التطبيق، ولها ترتيبها الأسبوعي ومنشور التهنئة 🏆 مثل باقي الألعاب

## المرحلة 16: إعادة التصميم
- تصميم جديد مبني بإضافتي **ui-ux-pro-max** و**frontend-design**: أسطح مسطّحة بلا ظلال، غرافيت وأخضر القطيفة،
  خط Reem Kufi للعناوين، و«شريط المتر» الأصفر كعنصر مميّز واحد
- التفاصيل والقواعد في `design-system/cher-meuble/MASTER.md`

## المرحلة 17: قراءة الفاتورة من صورة
- في **فاتورة شراء جديدة** (المشتريات) وفي **طلبية جديدة** (المبيعات): زر «تصوير فاتورة…» يفتح الكاميرا أو المعرض
- Gemini من Google أو Claude من Anthropic (حسب المفتاح المضبوط) يقرأ الصورة ويملأ: المورد/الزبون، التاريخ، رقم الفاتورة، الأسطر (الكمية، الوحدة، السعر)، التخفيض والمجموع
- يتعرّف على الموردين والمواد والزبائن الموجودين؛ وما ليس موجودًا يُضاف بضغطة («إضافته كمورد/زبون جديد»، «+ مادة جديدة بهذا الاسم»)
- لا يُحفظ شيء تلقائيًا: النموذج يمتلئ، تراجع، ثم تضغط «حفظ». ويظهر تنبيه إن كان مجموع الفاتورة لا يساوي مجموع الأسطر
- للمدير فقط. التكلفة على حساب صاحب المفتاح: Gemini له حصة مجانية محدودة، وClaude تقريبًا بضعة سنتات (دولار) لكل فاتورة

- صورة فاتورة المورد تُحفظ مع الشراء تلقائيًا عند التصوير (أو «إرفاق صورة الفاتورة» يدويًا)، وتظهر في تفاصيل الشراء مع «تغيير / إضافة صورة». لا يراها إلا المدير (يتطلب `016_purchase_photo.sql`)

### تفعيل قراءة الفواتير (مرة واحدة)
1. مفتاح واحد يكفي، أحدهما:
   - **Gemini**: من https://aistudio.google.com → Get API key، ثم في Supabase → Edge Functions → **Secrets** أضف `GEMINI_API_KEY` = المفتاح (يبدأ بـ `AIza`)
   - **Claude**: من https://console.anthropic.com → API keys (مع رصيد)، ثم أضف `ANTHROPIC_API_KEY` = المفتاح
   - إن وُجد المفتاحان يُستعمل Gemini، إلا إذا أضفت `INVOICE_AI` = `claude`
   - نموذج Gemini الافتراضي `gemini-flash-latest`؛ لتغييره أضف `GEMINI_MODEL` = اسم النموذج
2. Edge Functions → Deploy a new function → الاسم: `scan-invoice` → الصق محتوى `supabase/functions/scan-invoice/index.ts` → Deploy (أعد النشر بعد كل تعديل على الملف)
3. صفحة «حالة النظام» تُظهر ✓ أمام «قراءة الفواتير من الصور (Gemini)» أو «(Claude)» عندما تكون الدالة منشورة والمفتاح مضبوطًا

لا تضع المفتاح أبدًا في Cloudflare أو في كود التطبيق: يبقى في أسرار Supabase فقط.

## المرحلة 18: الكتالوج، المواد اللازمة، الإسناد، الأرباح، الرسوم، النسخ، وبدون إنترنت
- **الكتالوج** (المزيد ← الكتالوج): منتجات بصورة وسعر ومقاس وقماش وأرجل، و**مكوّنات** كل منتج من المواد (لقطعة واحدة) مع تكلفتها وهامش الربح.
  رابط **كتالوج الزبائن** `/catalogue` يُرسل بواتساب: صور وأسعار فقط، بدون حساب وبدون المكوّنات. منتج «مخفي عن الزبائن» لا يظهر فيه
- **طلبية من الكتالوج**: زر «+ من الكتالوج» في نموذج الطلبية يملأ السطر (الاسم، السعر، المقاس، القماش، الأرجل)
- **المواد اللازمة** في تفاصيل الطلبية: مكوّنات منتجات الكتالوج × الكمية + ما تضيفه يدويًا، ناقص ما خرج لها، مقارنة بالمخزون (متوفر / ينقص X)
- **قائمة الشراء** (المزيد ← قائمة الشراء): كل ما ينقص للطلبيات المفتوحة مع التكلفة التقريبية، وإرسالها بواتساب أو طباعتها
- **ربح كل طلبية**: المواد المُخرجة + **تكاليف أخرى** للطلبية (نقل، عمل خارجي…)، الربح حتى الآن ونسبته، والربح المتوقع بعد باقي المواد؛ وفي التقرير عمودا «تكاليف أخرى» و«النسبة»
- **توزيع العمل**: «العامل المسؤول» في تفاصيل الطلبية؛ يظهر في الورشة («لك» أو «المسؤول: …»)، مع «المُسندة إليّ» للعامل، ويصله تنبيه (بعد إعادة نشر send-push)
- **رسوم التقرير الشهري**: آخر 6 أشهر — المقبوض والمصروف، والصافي النقدي لكل شهر، مع جدول الأرقام
- **نسخة احتياطية أسبوعية تلقائية**: عند دخول المدير، إن كانت آخر نسخة أقدم من 7 أيام تُحفظ نسخة كاملة في الخادم (تبقى آخر 12). في «حالة النظام»: «نسخة الآن» وتنزيل أي نسخة Excel أو JSON
- **إخراج المواد بدون إنترنت**: يعمل بآخر قائمة محفوظة، والحركات تنتظر في الهاتف وتُرسل وحدها عند عودة الشبكة (مرة واحدة فقط ولو أُعيد الإرسال)

يتطلب: `017_catalog_planning.sql`، ونشر الدالة الجديدة `backup`، وإعادة نشر `send-push`.

## المرحلة 19: إصلاحات المراجعة

- إخراج مادة أُعيد إرساله (بعد انقطاع الإنترنت) لا يُنقص المخزون مرتين.
- العامل لا يرى تكلفة المواد ولا أسعار الكتالوج؛ عامل موقوف لا يحذف صور الطلبيات.
- لا تنبيه مكرر لنفس الحدث؛ تغيير الرمز السري أو إيقاف حساب يُنهي جلساته المفتوحة.
- النسخة الاحتياطية الناقصة لا تحذف النسخ القديمة الكاملة.
- لا شراء أو منتج مكرر عند إعادة «حفظ» بعد خطأ؛ ضغطتان سريعتان على «تأكيد الإخراج» حركة واحدة؛ زر «إعادة المحاولة» لحركة رفضها الخادم.

يتطلب: `018_review_fixes.sql`، وإعادة نشر الدوال `send-push` و`manage-users` و`scan-invoice` و`backup`.

## التشغيل على الكمبيوتر
```
npm install
copy .env.example .env      (ثم ضع المفتاح العام)
npm run dev
```

## النشر على Cloudflare Pages
- الرابط: https://cher-meuble-erp-v2.pages.dev
- يُنشر تلقائيًا عند كل دفع (push) إلى الفرع `main`
- Build command: `npm run build`
- Build output directory: `dist`
- Environment variables: `VITE_SUPABASE_URL` و `VITE_SUPABASE_ANON_KEY` و `NODE_VERSION=22`

## الاختبارات
- `npm run test:db`: يشغّل كل ملفات `supabase/*.sql` على Postgres داخل Node ويتحقق من الأرقام والصلاحيات (بدون أي إعداد).
- `tests/e2e/run.sh`: اختبار شامل للتطبيق الحقيقي على Postgres وPostgREST والدالتين، بدور المدير والعامل. انظر `tests/e2e/README.md`.
